# 爬虫统一对比测试方案

> 2026-11-24 当前边界：Next.js 静态/轻量执行与完整浏览器运行时覆盖分开验收。复杂水合、布局和 RSC 预取链目前难以在无浏览器模式完整覆盖，建议 Browcrawler 补充；不据此删除冻结浏览器必测目标。当前范围见 [实现矩阵](../basecrawler/README.md#nextjs-无浏览器实现矩阵2026-11-24)。下文历史批次的通过结果不替代当前协议和误报修正后的验收。


## 1. 目标

使用同一批目标站点、相同的范围规则和可比的采集预算，持续比较不同工具的 URL 发现效果、有效性、运行时间与稳定性。每次运行都应生成逐站点结果表和汇总表，并保留原始输出，方便复核和重跑。

`basecrawler` 与 `browcrawler` 是两个独立参测工具，分别运行、分别记录版本和结果，不合并成一个“本项目爬虫”结果。

## 2. 工具范围与比较分组

### 2.1 通用爬虫对比组

以下工具直接参与逐站点爬取效果对比：

- 项目工具：`basecrawler`、`browcrawler`
- 外部工具：`katana`、`gospider`、`hakrawler`、`cariddi`、`URLFinder`、`crawlergo`、`Argo`、`jsowl`

每个工具都是独立参测项。`gocrawl` 和 `Zeno` 不在本方案范围内。若某工具在指定模式下不能输出 URL，应记录为“不支持/运行失败”，不得静默从报告中移除。

### 2.2 JavaScript 分析组

`JShunter` 主要分析 JavaScript 并提取路由或端点，输入输出口径不同于通用爬虫。它单独作为 JS 分析组报告，不与通用爬虫按整站 URL 总数直接排名。将每个站点发现的 HTML/JS 文件保存为同一输入语料，再比较其 JS 端点发现数、有效端点数和独有发现。`jsowl` 如使用 URL 输入进行端到端爬取，可进入通用组；如使用已保存 JS 语料分析，则也应单列该模式。

## 3. 目标站点集

### 3.1 站点选择

首轮目标分为安全训练站点和框架站点两组。前四个训练站点是 Acunetix 官方列出的测试目标；`testasp.vulnweb.com` 同时是 [basecrawler 历史基准](../basecrawler/BENCHMARK.md)的目标。框架组覆盖 Vue、React、Angular、Nuxt、Next.js 和 SvelteKit 生态。目标可用性会变化，每轮先做健康检查；无效目标记录原因并跳过，不计入工具失败。

| site_id | 起始 URL | 类型 | 允许主机 | 首轮用途 |
|---|---|---|---|---|
| `testasp` | `http://testasp.vulnweb.com/` | ASP、多页、历史锚点 | `testasp.vulnweb.com` | 必测，衔接已有基准 |
| `testphp` | `http://testphp.vulnweb.com/` | PHP、多页 | `testphp.vulnweb.com` | 必测，补充不同服务端站点 |
| `testaspnet` | `http://testaspnet.vulnweb.com/` | ASP.NET、多页 | `testaspnet.vulnweb.com` | 健康检查通过后纳入 |
| `testhtml5` | `http://testhtml5.vulnweb.com/` | HTML5、前端页面 | `testhtml5.vulnweb.com` | 健康检查通过后纳入 |
| `juice-shop` | `https://demo.owasp-juice.shop/` | Angular SPA、API | `demo.owasp-juice.shop` | 可选；低速率、只读访问，服务不稳定时跳过 |

Acunetix 的[官方评估文档](https://www.acunetix.com/support/docs/faqs/registration-evaluation/)列出了前四个测试目标。OWASP 将 Juice Shop 定位为安全训练和工具测试应用；其[官方文档](https://help.owasp-juice.shop/appendix/integration.html)说明公开演示实例没有可用性保证，并要求避免不必要的大量请求。因此该站点不能作为每轮必测门槛，优先考虑本地自建实例。

#### 框架站点目标

以下目标使用官方文档或教程入口页，覆盖常见前端/全栈框架。它们是公开站点而非专门为爬虫压测提供的靶场，因此使用低负载配置：深度 2、每站最多 100 个页面、每主机不超过 1 个请求/秒、并发 1，并遵守 robots.txt。请求速率必须由工具限速参数或本地限速代理保证；并发为 1 本身不代表每秒最多一个请求。静态组和浏览器组分别运行；遇到 robots 禁止、限流或服务异常时跳过该站点并记录原因。

| site_id | 起始 URL | 框架/站点类型 | 允许主机 |
|---|---|---|---|
| `framework-vue` | [Vue Guide](https://vuejs.org/guide/introduction.html) | Vue 官方指南与示例导航 | `vuejs.org` |
| `framework-react` | [React Learn](https://react.dev/learn) | React 官方学习文档 | `react.dev` |
| `framework-angular` | [Angular Tutorial](https://angular.dev/tutorials/first-app) | Angular 官方交互式教程 | `angular.dev` |
| `framework-nuxt` | [Nuxt Tutorial](https://learn.nuxt.com/en) | Nuxt/Vue 在线教程与 playground | `learn.nuxt.com` |
| `framework-nextjs` | [Next.js Docs](https://nextjs.org/docs) | React 全栈框架官方文档 | `nextjs.org` |
| `framework-sveltekit` | [SvelteKit Docs](https://svelte.dev/docs/kit/introduction) | SvelteKit 官方文档 | `svelte.dev` |

这组目标用于比较实际框架生态站点上的链接和页面发现效果，不等价于每种框架的本地真值测试。评估客户端路由、点击触发请求和懒加载 chunk 时，还应使用离线固定 fixture 或自托管示例应用。Nuxt 官方教程说明其 playground 本身使用 Nuxt；Next.js 官方文档将 Next.js 定义为 React 框架；Svelte 官方文档分别提供 Svelte 与 SvelteKit 文档。

默认每个站点只允许访问表中列出的精确主机；同属 `vulnweb.com` 的其他子域仍按外链处理。额外真实站点只在确认授权并写入目标清单后加入，不临时追加到某一轮。

测试只针对公开测试站点或明确授权的站点。禁止目录 fuzz、破坏性操作和表单提交；浏览器交互仅点击已知只读元素。运行前确认工具默认行为，关闭自动表单提交、主动 fuzz 和会产生写入的功能。

### 3.2 目标清单记录字段

后续执行时以清单维护目标，不在命令和报告里临时更换范围：

| 字段 | 说明 |
|---|---|
| `site_id` | 稳定的站点标识 |
| `profile` | `traditional`、`spa`、`interactive`、`mixed` 或 `framework:<name>` |
| `seeds` | 固定起始 URL 列表 |
| `allowed_hosts` | 站内范围的主机白名单 |
| `expected_mode` | `static`、`browser` 或两者 |
| `enabled` | 是否纳入本轮测试 |
| `notes` | 授权、限速、访问限制或失效情况 |

目标增删需记录变更日期和原因。历史结果使用当时的目标清单版本，不能用新清单覆盖旧结果。

## 4. 运行模式与公平性约束

### 4.1 静态模式

比较 `basecrawler`、`katana`、`gospider`、`hakrawler`、`cariddi`、`URLFinder` 和支持静态 URL 爬取的其他工具。统一起始 URL、允许主机、最大深度、最大请求数、超时和并发上限。参数名称按工具单独映射，无法等价设置时在报告中注明。

主对比中关闭 URLFinder fuzz、目录字典探测和其他主动枚举功能。每轮全局请求预算建议最多 500 个 URL/站点、深度 3、请求超时 10 秒、并发不超过 10；若目标站点要求更低速率，以站点限制为准，并将实际设置写入报告。

### 4.2 浏览器模式

比较 `browcrawler`、`crawlergo`、`Argo` 及其他启用浏览器的工具。固定 Chrome/Chromium 版本、可执行文件路径、起始 URL、主机范围和浏览器运行上限。最大页面数沿用每站总预算，最大并发标签页建议为 4；禁止表单提交、fuzz 和非只读操作。

静态模式和浏览器模式分别出表。不能因为浏览器工具请求量较高，就直接与静态模式的原始总 URL 数混排。

### 4.3 重复和顺序

正式基线中锚点目标每个工具至少执行 3 轮，并轮换工具顺序。首次框架覆盖先对每个框架目标跑 1 轮，检查范围、输出和站点负载；确认后再把选定框架纳入 3 轮基线。每轮记录开始时间、耗时、退出码、版本、命令参数、超时、限流和错误信息。

### 4.4 Windows 命令模板

以下命令来自 [basecrawler 历史基准](../basecrawler/BENCHMARK.md)，改为当前 Windows 工具目录的调用方式。每个命令按目标清单中的 `seeds` 单独运行；`$Target` 每次取一个起始 URL，输出由运行器分别保存到该站点、工具和轮次对应的原始结果文件。执行前确认本地版本和 `--help`，版本变化时记录实际版本。

```powershell
$Target = 'http://testasp.vulnweb.com/'
$Tools = 'C:\ISEC\Deving\crawlers\othercrawlers'
$SiteId = 'testasp'
$RunId = '01'
$Depth = 3
$MaxPages = 500
$Concurrency = 10
$Timeout = 10
$HostRate = 1
$OutputDir = Join-Path (Get-Location) "comparison-results\$SiteId\$RunId"
New-Item -ItemType Directory -Force $OutputDir | Out-Null
$OutFile = Join-Path $OutputDir 'browcrawler-discovered.jsonl'
```

在对应子仓库/目录执行命令；示例变量中的 `$Target` 每轮换成目标清单中的单个起始 URL。捕获每条命令的 stdout、stderr、退出码和耗时，输出保存到 `$OutputDir`。

#### basecrawler

```powershell
ac.exe -u $Target -d $Depth -c $Concurrency -timeout $Timeout -jsonl
```

与历史命令一致；确保当前构建的 `ac.exe` 在 `PATH` 中。

#### hakrawler

```powershell
$Target | & "$Tools\hakrawler.exe" -d $Depth -t $Concurrency -timeout $Timeout -u -s
```

#### gospider

```powershell
& "$Tools\gospider.exe" -s $Target -d $Depth -c $Concurrency -m $MaxPages
```

历史基准中该工具曾运行失败；每轮仍记录退出状态和输出，不能把历史失败当成本轮结果。

#### cariddi

```powershell
$Target | & "$Tools\cariddi.exe" -md $Depth -c $Concurrency -t $Timeout -plain
```

#### URLFinder

```powershell
& "$Tools\URLFinder.exe" -u $Target -d ([uri]$Target).Host -m 2 -s all -t $Concurrency -time $Timeout -max $MaxPages
```

与历史命令相比增加目标主机约束和最大 URL 数；不启用 `-z` fuzz。若主机约束未生效，应停止运行并先修正适配器。

#### browcrawler

在 `browcrawler` 模块目录运行：

```powershell
go run ./cmd/browcrawler --config config.yaml --url $Target --scope-mode fqdn --depth $Depth --max-pages $MaxPages --host-rate $HostRate --interactions 0 --no-forms --obey-robots --discovered $OutFile
```

`--no-forms` 禁止表单提交，`--interactions 0` 关闭点击交互；该命令定义浏览器组的只读基础模式。如需比较动态点击发现，应另设只读交互配置并单独报告。

运行 VulnWeb 目标时使用示例值（深度 3、最多 500 页、并发 10）；运行框架站点时先设置 `$Depth = 2`、`$MaxPages = 100`、`$Concurrency = 1`、`$HostRate = 1`。如果某工具不支持其中一项，记录实际值，并确认请求仍受主机范围和低速率限制。

`gospider` 等工具若因 Windows 运行问题无法完成，仍在逐站点表保留失败行。`URLFinder -m 2` 的历史结果曾包含大量外链；本方案添加 `-d` 主机约束，并由统一归一化器再次按 `allowed_hosts` 过滤。所有工具都必须在请求发出前限制目标主机；不支持可靠主机限制的工具须经允许主机白名单代理运行，不能仅靠结果后过滤来掩盖额外外站请求。

`crawlergo`、`Argo`、`katana`、`jsowl` 和 `JShunter` 使用各自经过 `--help` 核验的参数适配器，适配器必须写入同一预算、范围和输出规范。`crawlergo`/`Argo` 归浏览器组；`JShunter` 归 JS 分析组。新增或升级工具时先做单站烟测，确认参数确实生效后再跑完整目标集。

## 5. 结果归一化与有效性复核

保留工具原始输出。归一化结果至少包含：`site_id`、`tool`、`mode`、`run_id`、`raw_url`、`normalized_url`、`source_type`、`status`、`content_type` 和 `in_scope`。

URL 归一化规则：

- 去除 fragment；统一 scheme 和 host 大小写；移除默认端口；解析 `.`/`..` 路径段。
- 保留查询参数及重复参数，不擅自删除参数或合并不同查询值；原始 URL 始终保留供复核。
- 相对 URL 按页面最终 URL 解析；无法解析的项计为无效输出，不计入唯一 URL 数。
- 静态资源、页面 URL、JS 中提取的端点和 robots/sitemap 来源分类型统计；如果工具无法提供来源，标记为 `unknown`，不要猜测来源。
- 站内、外链按该站点清单中的 `allowed_hosts` 判断，不依赖工具自身的 scope 统计。

对工具间差异 URL 做独立状态复核。自动核验脚本只发 HEAD，不发送 GET/POST，避免请求带副作用的路由；HEAD 返回 405/501 标记为 `head_unsupported`，不能据此认定 URL 不存在。单次 404/410 也不能排除软 404；只有重复核验并排除软 404 后才标记为 `gone`。2xx/3xx 仅表示 HEAD 可访问，不代表页面内容或 API 有效；401/403、429、5xx、DNS/TLS 错误、超时和不稳定响应均为 `inconclusive`，不归为爬虫错误或已删除 URL。

## 6. 指标定义

按每个站点、工具、模式和轮次统计：

- **唯一站内 URL**：归一化后符合站点范围规则的 URL 数。
- **可访问 URL**：复核为 2xx/3xx 的唯一 URL 数；抽样复核时同时报告样本量。
- **外链数/比例**：范围外 URL 数及其占全部唯一 URL 的比例。
- **无效 URL 比例**：确认 gone 或软 404 的 URL 数占已复核 URL 样本数的比例。
- **独有发现数**：仅该工具发现，且复核仍可访问或属于有效 API 路由的 URL 数。
- **运行耗时、退出码、请求失败数和超时数**。

真实站点没有稳定的完整真值集，因此不将总 URL 数称为召回率，也不把 URL 数最多的工具自动判为最好。离线固定页面测试可以使用已知真值集计算精确率和召回率；真实站点报告使用覆盖量、有效率、独有有效发现、外链比例和耗时共同评估。

## 7. 必须输出的结果表

### 7.1 逐站点、逐工具表

每次运行的主结果必须有如下列，不能只提供总数或文字摘要：

| 站点 | 类型 | 模式 | 工具 | 版本 | 轮次 | 唯一站内 URL | 可访问 URL | 外链数 | 无效 URL 比例 | 独有有效发现 | 耗时 | 退出状态 |
|---|---|---|---|---|---:|---:|---:|---:|---:|---:|---:|---|
| testasp | traditional | static | basecrawler | 记录值 | 1 | — | — | — | — | — | — | — |
| testasp | traditional | static | browcrawler | 记录值 | 1 | — | — | — | — | — | — | — |

真实运行时逐工具逐站点填入数值；失败项保留行并说明失败原因，不用空白或删除该行。

### 7.2 汇总对比表

逐站点表之外，提供每种模式一个汇总表，至少展示有效站点数、唯一站内 URL 的中位数、可访问 URL 的中位数、独有有效发现总数、外链比例中位数、耗时中位数和运行成功率。样本数和失败站点必须可见，不能将不同模式混成一个排名。

### 7.3 差异 URL 表

另附工具独有 URL 清单，字段为：站点、URL、发现工具、模式、复核状态、HTTP 状态、内容类型、最终主机、复核时间和备注。该表用于确认工具差异是否来自 URL 已失效、站点漂移、外链范围或真实爬取能力差异。

## 8. 每轮报告与复现材料

每次测试保留以下内容，并用同一个 `run_id` 关联：

1. 目标清单版本和运行环境摘要。
2. 每个工具的版本、哈希、实际命令、退出码、耗时和原始输出。
3. 归一化 URL 明细及 URL 复核结果。
4. 逐站点结果表、模式汇总表和差异 URL 表。
5. 相对前次基线的新增、缺失、状态变化及失败站点说明。

只有在目标预检有效、工具运行成功且差异 URL 完成复核后，才更新比较基线。站点失效、目标集变更或归一化规则变化时，应建立新的基线版本，不覆盖旧结果。

## 9. 执行顺序

1. 检查目标清单、授权范围、站点可用性和浏览器依赖。
2. 运行本地离线 fixture，验证解析与 URL 归一化口径。
3. 对当前锚点站点执行每个工具的一轮烟测，确认命令、输出和资源预算正确。
4. 对有效站点按静态组、浏览器组分别完成 3 轮采集。
5. 归一化结果，生成逐站点表和汇总表。
6. 复核差异 URL，分类为有效独有发现、站点已失效、范围外、软 404 或无法判定。
7. 生成带版本号的报告；确认有效后才更新基线。

### Python 运行器

项目提供 `tools/crawler_compare.py`，使用 Python 标准库，不需要额外安装依赖。先查看清单和本机工具状态，再预览执行矩阵：

```text
python tools/crawler_compare.py list-targets
python tools/crawler_compare.py list-tools
python tools/crawler_compare.py self-test
python tools/crawler_compare.py plan --targets testasp --tools basecrawler,browcrawler,katana
```

核心工具在两个 VulnWeb 锚点上跑三轮；框架覆盖先用核心静态、浏览器和 JS 工具各跑一轮：

```text
python tools/crawler_compare.py run --targets testasp,testaspnet --tools basecrawler,browcrawler,katana,hakrawler,gospider,cariddi,urlfinder,jsowl,jshunter --rounds 3
python tools/crawler_compare.py run --targets framework-vue,framework-react,framework-angular,framework-nextjs,framework-sveltekit --tools basecrawler,browcrawler,katana,jsowl,jshunter --rounds 1
```

每次执行会创建独立结果目录，包含原始 stdout/stderr、命令与版本记录、逐轮 `results.csv`、URL 明细 `urls.csv`、按工具聚合的 `aggregate.csv` 和 `summary.md`。重复性用逐轮站内 URL 集合的 Jaccard 相似度表示。默认结果位于 `artifacts/crawler-comparison/<run_id>`，也可用 `--output-dir` 指定。长任务中断后可用 `python tools/crawler_compare.py recover --output-dir <run目录> --targets testasp,testaspnet` 重建指定目标的报告；恢复记录会注明退出码未知。对比完成后，按每个主机最多 20 条复核工具独有的站内 URL：

```text
python tools/crawler_compare.py verify --run-dir <run目录> --limit-per-host 20 --pause 1
```

复核输出 `verification.csv` 和 `verification.md`，使用 HEAD 并跟随跳转；站点不支持 HEAD 时记录 `head_unsupported`，不会回退为 GET。403/429、超时和服务端错误单独列出，不直接判为 URL 不存在。

框架目标默认深度 1、每工具最多 20 页、每主机每秒 1 次导航。Katana 以 JSONL 输出 URL 字段但省略响应正文。browcrawler 使用 `browcrawler/third/obscura/obscura.exe`；运行器生成该轮独立配置并沿用项目代理设置。`crawlergo` 会自动填写并提交表单，默认跳过；只有对授权测试实例运行时才显式传入 `--allow-form-submit`。运行器不会自动验证 URL 当前是否可访问，报告中的 URL 数量只表示工具发现结果。

本机实测 Argo 因启动 `leakless.exe` 被系统拒绝而失败，基线命令暂不包含 Argo；修复该运行环境后再加入。VulnWeb 锚点默认并发 4、每主机每秒 2 次请求。

## 10. 与现有资料的关系

### 三轮统一复测与接口契约验证（2026-11-19）

专项入口为 `tools/katana_regression.py`，固定三个独立工具模式：basecrawler 无浏览器、Katana 静态、Katana 浏览器。每个站点顺序执行，跨站点并行，三轮轮换执行顺序；不改变 basecrawler 已有相似 URL 过滤。

```text
python tools/katana_regression.py --output artifacts/crawler-comparison/<新目录> --rounds 3 --seconds 60 --pages 80 --depth 2 --rate 2 --workers 3 --strategy breadth-first
python tools/katana_regression.py --output artifacts/crawler-comparison/<扩展目录> --targets testphp,framework-nuxt,juice-shop,app-react-todomvc --rounds 3 --seconds 45 --pages 50 --workers 3
python tools/crawler_contract_benchmark.py --output artifacts/crawler-comparison/<接口契约目录>
python tools/crawler_gap_analysis.py --input artifacts/crawler-comparison/<三轮目录>
python -m unittest discover -s tools -p test_katana*.py
python -m unittest discover -s tools -p test_crawler_gap_analysis.py
```

本机需要代理时显式追加 `--proxy socks5://127.0.0.1:10808`，三个模式及 HTTP 核验使用同一代理。该地址是本机配置，不是通用默认值。浏览器模式包含本机已验证的 `-ho disable-features=HttpsUpgrades,HttpsFirstBalancedModeAutoEnable`，解决传统 HTTP 靶场被 HTTPS 升级机制阻止的问题。

默认主集为 testasp、testaspnet、Vue、React、Angular、Next.js、SvelteKit。实际应用扩展集增加 Nuxt 学习应用、Juice Shop、TodoMVC React，目录同时提供 `app-vue-todomvc`；不要同时对同域名的 React/Vue TodoMVC 启动独立并行测试。

每轮保存实际命令、二进制 SHA256、进程运行秒数、完成原因、原始输出和候选；全轮 Katana 两模式并集冻结为相同参考集，逐 URL HTTP 核验后生成 `comparison.jsonl`、`verification.jsonl`、`effective.json`。根目录输出 `regression.json` 和 `summary.md`，包含三轮耗时、均值/中位数、覆盖率及最低 Jaccard 稳定度。

正式单站通过需要：至少三轮、每轮有效 GET 页面/API 覆盖 ≥95%、无待核验 URL、三个模式运行有效，且每个模式轮间最低 Jaccard ≥0.90。固定主集至少 80% 站点通过才达总体门槛；扩展集单列，不能替换失败主集站点。JS 执行错误及请求失败保留为部分失败，不能用退出码 0 掩盖。

三轮共享一个 HTTP 证据快照，不代表三次独立可用性测量；页面/时间预算约束下的运行秒数也不等于同等工作量吞吐。400/401/403 只在发现记录具有真实同源引用时尝试携带 Referer/Fetch Metadata 复核，并记录初始状态及复核配置。`200 null` 只能证明匿名 JSON 响应，不证明登录业务成功。

`--resume` 只允许配置、二进制哈希均相同的目录。修改代码后二进制变化应另建目录。若仅复测 basecrawler，可用 `--base <exe> --reference-runs-from <原三轮目录>`：必须匹配目标、轮数、预算、策略、代理及 Katana 哈希，复制原始 Katana 记录并写入 `provenance.json`，不把复用的参考记录描述为新执行。

普通恢复会重试原先部分失败的爬取轮次；若只需继续 HTTP 核验，使用原参数加 `--resume --verify-only`，保留已有运行记录。`--summarize-only` 仅汇总已完成的所有轮次，不进行网络访问。

接口契约脚本使用本地真实 HTTP 接收端，检查 GET/POST/PUT/PATCH/DELETE、路径模板、查询字段、JSON 编码和表单编码，区分“发现”“生成”“实际发送”。basecrawler 分别使用默认每接口 3 条与用户指定 5 条；固定输入不足时单列原因，不伪造数量。测试包含多 Source Map 客户端隔离；线上覆盖测试保持 testfill 关闭，避免把主动测试流量和链接发现混在一起。

差异归因脚本读取已完成的三轮结果，逐个缺失 URL 关联 Katana 的引用来源与 basecrawler 的实际请求/发现记录，输出 `gap-analysis.json`、`gap-analysis.md`。区分父资源请求失败、深度外已发现、预算下未访问、父资源已访问但需解析/运行时复现、缺少来源证据。后一类仅为待复现项，不能直接标记为已确认解析缺陷。

### basecrawler 无浏览器与 Katana 双模式专项（2026-11-18）

运行器：`tools/katana_effective_compare.py`。固定目标：testasp、testaspnet、framework-vue、framework-react、framework-angular、framework-nextjs、framework-sveltekit；目标实际 URL 复用 `crawler_compare.TARGETS`。

```text
python tools/katana_effective_compare.py run --output artifacts/crawler-comparison/<新基线> --seconds 60 --pages 80 --depth 2 --workers 3
python tools/katana_effective_compare.py verify --output artifacts/crawler-comparison/<新基线> --workers 3
python tools/katana_effective_compare.py summarize --output artifacts/crawler-comparison/<新基线>
```

可用 `--strategy depth-first` 对齐深度优先策略，或显式指定 `--proxy` 为各模式使用同一代理。策略变化要另建目录。历史专项快照中 basecrawler 使用 breadth-first、Katana 使用其默认 depth-first，不能把该差异当作解析能力差异。`--resume` 仅复用已完成进程；修改预算、二进制或策略时使用新目录，不混用历史配置。

三个独立模式为 basecrawler、katana-static、katana-browser，basecrawler 不启动浏览器。启用双方相似 URL 过滤；按 HTTP 方法和参数契约保留差异，不因输出行数较少判为漏爬。记录命令、进程墙钟秒数、退出状态、二进制哈希和原始输出。声明的工具预算并不等于相同的实际 HTTP 请求数，耗时不可单独作为速度排名。

专项参考集是 Katana 两模式候选的并集。逐条 GET 核验页面/JSON，排除 404/410、已确认软 404、SPA 首页回退和静态资产；网络错误、拒绝访问和截断单列待核验。HTML 别名需要跳转或响应正文一致的证据，JSON 正文相同不代表两个 API 等价。完整接口方法、参数和业务行为另行验收。

输出每站 `effective.json`、逐 URL `comparison.jsonl`、`verification.jsonl` 和汇总 `summary.md`。正式门槛为固定目标中至少 80% 的站点覆盖至少 95% 已核验有效参考，且参考运行无失败、无待核验项。Katana 空结果标记 `empty_unverified`；全部请求失败标记 `failed_requests`，即使退出码为 0 也不能通过。参考失败会使正式验收未通过，不得宣称 basecrawler 胜出。

`basecrawler/BENCHMARK.md` 中的 `testasp.vulnweb.com` 结果作为历史参考和锚点，不直接作为新一轮完整基线。该文档提到的 `basecrawler/tools` 基线脚本在当前工作区中不存在；实现自动化时，应按本方案补齐统一运行器、URL 归一化/比较器和表格报告生成，不依赖未检出的脚本。

### 固定参考结果，仅重跑 basecrawler

后续回归以本节为准。Python 入口为 `tools/katana_frozen_compare.py`。每站点、每个 Katana 模式分别选择历史记录中去重后 `(method,url)` 最多的**单次扫描**；同模式不合并多轮。静态和浏览器模式共同组成对标参考。失败运行仍保留失败状态，不因候选数量多而变成成功。

```text
python tools/katana_frozen_compare.py freeze --source artifacts/crawler-comparison/katana-current-three-rounds-20261119 --source artifacts/crawler-comparison/katana-current-expanded-20261119 --output artifacts/crawler-comparison/katana-frozen-max-v1
python tools/katana_frozen_compare.py run --reference artifacts/crawler-comparison/katana-frozen-max-v1 --output artifacts/crawler-comparison/<新批次> --base basecrawler/bin/basecrawler.exe --rounds 3 --workers 3
python tools/crawler_gap_analysis.py --input artifacts/crawler-comparison/<新批次>
```

冻结命令只执行一次，已有目录禁止覆盖。`frozen.json` 保存来源、配置、历史耗时及候选/原始结果哈希。后续 `run` 只启动 basecrawler，校验冻结结果及运行元数据；不启动 Katana 或浏览器。`--targets` 可选逗号分隔目标 ID，主集和扩展集分别验收。`--resume` 恢复相同配置；`--verify-only --resume` 只恢复核验。

变更冻结口径后，必须先用 `compare-saved --reference <冻结目录> --source <旧批次> --output <重评分目录>` 对旧 basecrawler 记录重新评分，再比较修复前后；它不启动爬虫，必要时只补 HTTP 核验。禁止把旧跨轮并集分母与新单次最大分母直接相减当成优化收益。

每轮保留 `run.json` 的实际耗时、二进制哈希、请求数量和完成原因。汇总输出 `summary.md`、`regression.json`，逐 URL 证据由 `gap-analysis.json` 提供。三轮稳定性只检查持续修改的 basecrawler，要求 Jaccard ≥0.90；覆盖率及失败/待核验门槛沿用原方案。参考耗时属于历史单次记录，不能据此直接宣称同环境速度优势。复用的 HTTP 证据必须注明历史来源，不代表重新确认了全部 URL 当前可用性。

basecrawler 默认独立资源递归上限 `--resource-depth 4`，页面 `--depth` 保持独立，`--resource-depth 0` 恢复旧深度行为；总请求数、时长、速率和相似 URL 过滤继续生效。通用修复测试必须更换域名、部署目录及变量值，并包含未知输入/作用域遮蔽负例。不得从参考工具 URL 反向注入爬虫、写死站点或构建 ID，也不得仅凭 canonical 合并不同查询 URL。

第二批通用修复验证约束：即使使用 `--no-testfill`，GET 表单也可按原始控件默认值生成一次默认提交请求；这与 testfill 每接口生成测试数据分别记录。保留原接口契约，不把未勾选 checkbox、未选中的候选值或提交按钮任意加入请求。默认值无法完整表示的表单仅保留契约，不输出截断的伪默认请求。

有限枚举模板是静态发现的潜在接口，不代表框架已运行或业务验证成功。只使用词法作用域内显式对象键和支配请求的成员检查，排除未知/被修改/遮蔽的配置；最多 16 个域值，并沿用 256 个上下文发现上限。测试必须同时核对发现记录与受控 HTTP 服务收到的真实 GET 请求；非 GET 请求仍由 testfill 承担实际发送。真实站点发现与历史 HTTP 核验有效性分别表述。

资源调度验证必须包含“很多同层页面 + 多级依赖 + 固定总请求数”的夹具，确认深层依赖实际收到请求，并检查请求总数、资源深度、导航深度和去重仍有效。主集/扩展集保持原配置三轮运行，禁止通过提高预算或删除失败站点制造覆盖率提升。

### 协议感知核验与执行证据（第三批修复）

每站除 `comparison.jsonl`、`effective.json` 外，输出 `metrics.json`，分别记录发现的 method/URL、已观察请求及成功响应、basecrawler 实际调度次数、分析失败、执行限额、未访问量和墙钟耗时。实际调度次数不包含 bootstrap、重试或重定向的额外网络跳数；Katana 未提供完整网络计数或 JS 异常统计时填未知，不可填零。相似 URL 过滤仍启用，发现数与实际请求数不能互相替代。

RSC 请求需从原始请求中恢复 Rsc、Prefetch、Segment/State、Next-Url 等上下文；同时回放观察到的浏览器 UA、Accept 和语言，避免服务器内容协商返回 Markdown。只有成功的 text/x-component 响应才进入有效 RSC 参考集；普通 HTML、协议上下文缺失、截断和请求错误分别记为待核验或失败。不同缓存键仅在其他查询参数、协议上下文及响应哈希等价时合并；`/_tree` 与页面段预取必须分别统计。

修改评分口径时先重评保存结果。例如只校正 Next.js，不启动任何爬虫：

```text
python tools/katana_frozen_compare.py compare-saved --reference artifacts/crawler-comparison/katana-frozen-max-v1 --source artifacts/crawler-comparison/generic-repair-stage2-20261118/primary --targets framework-nextjs --output artifacts/crawler-comparison/stage2-next-protocol-rescored-20261118
```

修正 UA 后，旧 Next.js 分母由旧记录的 14 变为 31，旧爬虫结果为 13/31；不得与原 13/14 直接比较并宣称退步。新增有效项主要是原先错误内容协商遗漏的协议响应，并不代表站点新增长了同等数量的普通页面。

保留严格验收与发现覆盖两个维度。URL 覆盖 100% 仍可能由于分析失败、请求失败、超时、未解决参考项或三轮不稳定而不能正式通过。`gap_evidence` 标记父页面未访问、发现未访问或历史边未再发现；历史父页面当前返回 200 并不能单独证明解析器缺陷，也不能证明历史子 URL 已失效，必须检查响应内容。

`config.json` 增加评分脚本 SHA-256；每轮保留二进制哈希、运行时间及冻结参考来源。Katana 继续只使用历史最多的单次结果，不重复扫描、不跨轮拼接。页面预算并不代表两种工具具有相同总网络成本，耗时对比只能作为当前预算和配置下的观测。

### 浏览器交互抽样

统一运行器默认关闭 Browcrawler 点击交互（`--brow-interactions 0`）。只在预先检查过、点击无写副作用的目标上使用 `--brow-interactions N` 做有限点击验证；运行器仍传入 `--no-forms`，且不启用 fuzz。目标按清单限制深度、页面数、主机速率并遵守 robots.txt。

对只读在线框架目标进行交互抽样时，可用：

```powershell
python tools/crawler_compare.py run --targets framework-sveltekit --tools basecrawler,browcrawler,katana --rounds 1 --brow-interactions 10 --pause 1
```

该命令仅启用 Browcrawler 的有限控件点击，不提交表单。报告中的 `metadata.json` 和逐工具 `command.json` 会保存交互预算及实际参数。每轮 Browcrawler 的 `--out`、`--report`、`--metrics` 分别写入该轮目录下的 `traffic.jsonl`、`crawl-report.json`、`metrics.jsonl`。

### 爬取完成状态

`results.csv` 与 `summary.md` 分开记录进程状态和爬取完成状态。Basecrawler 从 `scan-report.json` 读取完成标记与原因；Browcrawler 优先读 `crawl-report.json`，并从 `[completion]` 日志补齐原因；Katana 在实测时长达到 `-ct` 时间预算（误差阈值为 5% 或 2 秒）时标记为 `timed_out`。其他工具没有可读的完成证据时记为 `unknown`，不视为完整。退出码为 0 只代表工具进程正常结束。
